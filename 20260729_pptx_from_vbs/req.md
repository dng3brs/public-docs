# スライド作成要件定義書：MCP vs Skills 比較

## 1. 基本情報
- **テーマ**: MCPとSkillsを比較する1枚のスライド作成
- **ターゲット層**: 生成AIを活用したシステム開発の企画者・エンジニア・アーキテクト（技術的仕組みや実務での使い分けに関心がある層）
- **メインメッセージ**: 
  > 「MCPは『標準化された接続プロトコル』、Skillsは『特定の振る舞いや手順の拡張機能』であり、両者は対立するものではなく補完関係にある」

---

## 2. スライドレイアウト・デザイン要件
- **全体レイアウト構成**:
  - **上部ヘッダー部**: メインメッセージ（結論）を大きく配置
  - **中央メイン部**: 5つの比較観点に基づく対比表
  - **下部フッター部**: 結論・使い分けの指針（補完関係）およびレイヤー構造の概念図
- **配色・デザインスタイル**:
  - **ベース色**: 白 / ライトグレー（可読性重視）
  - **MCPキーカラー**: 青系
  - **Skillsキーカラー**: 緑系
  - **まとめ・強調キーカラー**: オレンジ系（最下部の補完関係部分に使用）

---

## 3. 比較対比表コンテンツ（中央メイン部）

| 比較観点 | MCP (Model Context Protocol) | Skills (Agent Skills等) |
| :--- | :--- | :--- |
| **1. 定義・位置づけ** | 外部データやツールとLLMを接続するための標準プロトコル（基盤レイヤー） | エージェントに特定のタスクや手順を実行させるための手順集・機能拡張（アプリケーションレイヤー） |
| **2. 主な目的** | ツール・データソース接続の共通化・再利用性の向上 | 特定ドメインのタスク実行手順（ワークフロー）の自動化・高度化 |
| **3. 拡張性・標準化** | 高い（共通規格に従うことで、一度作れば多様なクライアントで利用可能） | プラットフォーム/フレームワーク固有の依存度が比較的高い |
| **4. 実装・制御の単位** | インターフェース、データ形式、認証・リソース取得 | プロンプト群、コード実行ブロック、ツール利用ルール |
| **5. 適用シーン・使い分け** | DBや外部SaaS（GitHub, Slack等）との標準接続経路を確立したい時 | 専門的な作業手順（リサーチ、データ解析など）をLLMに再現させたい時 |

---

## 4. レイヤー構造表現（下部フッター部）

両者が対立せず補完関係にあることを視覚的に示すため、以下の3階層構造を概念図として配置します。


```

+-------------------------------------------------------+
|  [ 上層 ] Skills（タスク手順・指示・ワークフロー）     |
+-------------------------------------------------------+
│
▼
+-------------------------------------------------------+
|  [ 中層 ] MCP（標準接続プロトコル・インターフェース）   |
+-------------------------------------------------------+
│
▼
+-------------------------------------------------------+
|  [ 下層 ] 外部システム / DB / API / Tools             |
+-------------------------------------------------------+

```
